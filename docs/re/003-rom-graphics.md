# ROM 圖塊來源與 HD 比較原型

日期：2026-10-11。對應 [#5](https://github.com/wicanr2/taipei/issues/5)。
入口：[CONTEXT.md](../../CONTEXT.md)。工具：[rom_catalog.py](../../workspace/tools/rom_catalog.py)。

## 已證實的容器結構

輸入為[輸入基線](001-input-baseline.md)列出的原版 ROM，使用 Python 3.13.15，
Docker `python:3.13-slim`。以下位址全部是 ROM 檔案偏移，不是執行期或 IDA 位址。

| 欄位 | 檔案偏移與資料 |
|---|---|
| 成員數 | 0，16 位元小端序；RS201.ROM 為 69，RS201A.ROM 為 49 |
| 成員紀錄 | 從 8 起，每筆 16 bytes |
| 成員資料位置 | 紀錄內 +10，32 位元小端序 |
| 成員資料長度 | 紀錄內 +14，16 位元小端序 |
| 紀錄內其餘 10 bytes | 未知，保留原 bytes，不當成檔名或語意 |

兩個容器的全部成員依序連續，最後成員終點等於檔案長度，沒有越界或未解尾端。
首個成員各為 768 bytes。其 RGB 色盤用途為強推論，尚未逐色比對寫入 DAC 的完整控制流。

## 已證實的原始點陣圖庫

部分成員開頭為 16 位元圖數，後接每圖的 16 位元成員內偏移。
首圖偏移等於 `2 + 圖數 × 2`。每圖開頭是 16 位元寬、高，後接每點一 byte 色號。
工具只在全部偏移合法、嚴格遞增、每圖長度恰為 `4 + 寬 × 高` 時分類。
其他成員保留未知，不猜解壓縮法。

| RS201.ROM 成員 | 圖數 | 來源 |
|---|---|---|
| 34–37 | 各 96 | 每圖 9×9 原始色號 |
| 38、40、41 | 各 180 | 每圖 9×9 原始色號 |
| 39 | 75 | 每圖 9×9 原始色號 |
| 59 | 135 | 每圖 9×9 原始色號 |

這些圖塊合計 1,134 個來源圖，不代表 1,134 個不同圖像。內容可見地形、道路、建物與設施，
這項分類只是視覺導覽，未據此命名正式規則或建築種類。
工具也辨識其他大小的完整原始點陣圖庫，全部成員及圖像雜湊保存在本機 `catalog.json`。

## 原版畫面匹配

使用 dosgolem 的診斷地圖 `workspace/runs/city-native.bin`，在 9×9 格線比較完整原始色號。
抽樣矩形中 405／405 格精確匹配原始圖塊。最佳格線的 `x mod 9=5`、`y mod 9=7`。
逐格位置及所有相同圖像的來源別名保存在 `workspace/runs/rom-catalog/catalog.json`。
沒有用 RGB 相似度、AI 辨識或猜測圖像代替匹配。

這只證明該張畫面的點陣來源。繪製時機、地圖捲動、遮擋、清除、選取高亮與動畫仍待驗證。
此快照源自診斷續跑，不能取代正常玩家路徑。正式 HD 仍需獨立 READY 契約。
