# 年度預算視窗的 HD 原型回退

狀態：**DRAFT**。對應 [#26](https://github.com/wicanr2/taipei/issues/26)，只修正 [010](010-hd-live-prototype.md) 已有的原版視窗整幀回退契約。

## 實際證據

[#25](https://github.com/wicanr2/taipei/issues/25) 從正常原版冷啟動建立空城市，使用原版鍵 `3` 後持續運行。60 個固定步數擷取中，`running-03`、`running-32` 顯示年度「預算配置」視窗。原版日期與文字均由實際畫面辨識，沒有注入視窗狀態。

兩幀的 BIOS 阻塞狀態皆為 false，頂部城市 UI 指紋相同，原型因此仍覆繪視窗外的 29 格地景。原版視窗內容未被蓋掉，但這與整幀回退契約不符。修正前證據保留於 `workspace/runs/hd-runtime-before-guard/`。

## 已辨識狀態

固定 EXE SHA-256 為 `798db7f69e287690814f4e7b588be733fc0ad28a6ad943eb397d1f82528db3b3`。原生色號畫面中，標題矩形 `(18,38,99,22)` 包含固定可見的「預算配置」標題與邊框。兩份正常收據的 2178 bytes SHA-256 均為 `a93af2ea621191dc51663f84eee9ebc40672d149d585a1458b9edf3c60e872bb`；正常城市同矩形為另一雜湊。矩形只作狀態辨識，不改排版或字型。

證據等級：已證實，限上述原版與完整可見標題狀態。不宣稱辨識視窗的所有開啟、關閉相位或全遊戲模態視窗。

## 原型契約與預登記驗證

- 既有模式、頂部 UI 與色盤條件通過後，辨識預算標題時，整幀保留原版四倍，`Painted=0`，原因為 `budget-window`。
- 原版色號與色盤不變；不呼叫、攔截或改寫原版預算功能。
- 以兩份實際年度視窗收據驗全幀 RGBA 與原版四倍相同。正常城市與既有模態、素材、色盤、未知原點回退測試維持。
- 重新執行正常冷啟動與未暫停時間推進，至少捕捉一份真實預算視窗，驗原版整幀回退及後續城市恢復。固定步數抽樣不能證明未擷取相位沒有閃爍。
- 字型、正式切換、其他 HD 批次及封包仍依 #6 的確認閘門。本修正不將 DRAFT 升為正式 HD。

## 已執行驗證

兩份實際年度收據的全幀回退與原版色號不變測試通過。正常冷啟動重跑的 60 份持續運行樣本中，`running-03`、`running-32` 均為 `budget-window`、覆繪 0 格，完整 1280×800 RGBA 等於原版四倍；`running-04`、`running-33` 恢復 433 格覆繪。其餘既有原型防護測試及 24 份捲動收據重新核對通過。

同一正常 GUI 輸入重播至 2,400,000,000 步，有／無 HD 的原版機器狀態相同，實際經過 107 次年度視窗回退。證據、雜湊與限制見 [持續運行研究](../re/007-running-city.md)。本契約維持 DRAFT，沒有以局部修正替代 #6 的產品定案。
