# 呈現重算與音訊連續性

狀態：READY。對應 [#64](https://github.com/wicanr2/taipei/issues/64)，回鏈 [041](041-local-promo.md)。

## 已確認原因

正式封包在預設收據頻率、無視訊錄影的正常冷啟動仍缺音訊資料。`workspace/runs/promo-v.1.0.0-20261015-r2/audio-probe.json` 記錄 20 秒期間 HD 僅產生約 12 秒 PCM，原版約 17 秒。不是原曲缺檔。固定 YMFM、原版 OPL 事件及虛擬時間沿 009。

診斷副本只加 Go CPU profile，未改規則。`promo-v.1.0.0-20261015-r3/hd-b/cpu.pprof` 的 25.36 秒 CPU 樣本中，`game.refresh` 占 8.31 秒，`Renderer.Render` 占 7.50 秒；每個更新均重畫完整 1280×800，即使原版畫面及來源觀察沒有改變。正式程式不收入 profile 掛勾。

快取與逐列展開後，r6 的 CPU profile 已降至 13.85 秒遊戲更新，但短缺仍存在。固定 Ebitengine v2.9.9 的 `internal/clock/clock.go` 第 67–111 行在排程落後約 83 ms 時同步主機時鐘，捨棄待追更新；`run.go` 的 SetTPS 契約明定只控制主機更新呼叫頻率。不能把 60 次主機更新當作可靠音訊時鐘。

## 最小修正契約

- 原版每個 `Step`、觀察呼叫、輸入、名義時鐘、YMFM、PCM 與存檔不變。
- r7／r8 證明增加主機更新預算未改善，不採用。實際播放器採每秒 30 次主機更新，按既有 PCM ring 消費補給；低於 350 ms 時同次更新可補最多八個既有批次，每批仍為 `StepsPerSecond()/60`。通常每更新兩批，保留完整觀察與音訊事件；主機更新頻率不作原版或音樂時鐘。靜音研究維持 60 次且每更新只執行一批。
- 只快取呈現。完整鍵包含原版 64000 色號、完整色盤、顯示模式、DOS blocked、原版／HD、語系、地圖原點、文字及插畫觀察版本。
- 來源觀察版本在既有已驗呼叫或逐字進度掛勾到達時遞增；不更改觀察到的語意。
- 快取保存不含前端浮層的畫面。每次回傳獨立繪製緩衝，Help／語系面板不污染下次畫面。
- 同鍵可重用畫面及統計；任何鍵變化重新執行既有 renderer。來源失配與原版回退沿既有規則。
- 完整呈現像素未變時不再次上傳相同 GPU 紋理；前端浮層也納入完整像素雜湊，不略過有變化的畫面。
- 主機追趕與音訊補給只執行原版步進及觀察，不重繪不會逐張顯示的中間畫面。既有單執行緒 Draw 每個顯示幀才呈現，收據另在序列化前 refresh 同一原版狀態，避免圖文跨代。不新增執行緒或限制顯示幀率。
- 收據 PNG 使用較快的無損壓縮，ZIP 沿既有 Store。檔名、JSON、原始像素與讀取契約不變。
- 原版四倍最近鄰展開採逐列複製，與原先逐點展開逐 byte 相同；不改縮放或色盤。
- 如修正不足以連續播放，保留失敗證據，再定位剩餘瓶頸，不調慢原曲、不自行換曲。

## 驗證與版本

1. 快取與無快取輸出逐像素相同；前端浮層清除、原版畫面／色盤／來源版本變化會更新。
2. 現有呈現、原版觀察、音訊測試通過；正常正式實包遊玩、F11／F12、原版存讀路徑不退步。
3. 相同音訊探針重跑，記錄 PCM／wall-clock 與 ring 缺資料；實際 WAV 另驗斷音、削波與 DC。
4. 新修訂版另建 tag 與三平台封包。舊 `v.1.0.0-20261015` 保留；人耳及 Windows／macOS 真機未驗仍保留。
